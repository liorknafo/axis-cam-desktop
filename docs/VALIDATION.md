## Sign in with ChatGPT

- Verified against a loopback stand-in for OpenAI's servers; no test that runs contacts OpenAI or the Keychain (the one Keychain test is ignored).
- First sign-in registers the app, exchanges the code with PKCE and validates the ID token (RS256 signature, issuer, audience, expiry, nonce). Wrong state, denial, timeout and each invalid token are refused.
- Tokens refresh before expiry and once after a 401, one refresh at a time, saved before use; fatal refresh errors and sign-out clear the saved sign-in. Before refreshing, the client reads the store again: a sign-in for the same account that another copy has already refreshed is adopted without a refresh request (two clients on one store make one token request), and it is refreshed with its own token only when it is itself near expiry. After a fatal refresh, a newer saved sign-in for the same account is used instead of being deleted, and another user's is not adopted. A saved set is adopted only when it expires later than the client's own and holds no refresh token the client has spent: when both saves of a refresh fail, the next expiry-driven refresh sends the rotated refresh-2, not the spent refresh-1 left in the store; a stored refresh-2 set that outlives the client's refresh-3 set is not adopted once refresh-2 is spent; and after a fatal refresh an older saved set is neither adopted nor deleted. While a refresh saves its rotated tokens, the client reports it (the close decision reads this).
- Streamed replies require completion; failures, refusals, early ends and each plan-usage error map to a clear state. Unsupported structured output falls back to plain JSON once. A reply larger than 4 MB is refused, and a refusal is shown as one line of at most 300 characters.
- Tokens never appear in settings or Debug output, and the account state the UI shows holds only the name, the email and whether plan usage is granted.
- Live check with the user's account (3 October 2026; not a test): the first attempt was rejected because the installation ID was not in `urn:uuid:` form. After matching OpenAI's reference kit (ID format, `/auth/callback`, client ID and `azp` checks), registration and browser approval succeeded.

## AI planner

- Verified with a scripted stand-in for the model, and for the OpenAI backend with the loopback stand-in; no test contacts OpenAI. A live planning run needs the user's ChatGPT sign-in and is not part of this evidence.

- A good first proposal gets one coverage round, and the passing plan with the larger exposed share is kept; a first plan that leaves nothing covered makes one request. A plan that already passed survives a later request that fails, cannot be parsed or does not pass; the outcome counts the requests made, names the request whose plan won and keeps a follow-up API error. Of two different check failures, the last is reported. An API error, or a check that fails to run, after a failed check keeps that check's problems (bounded); a check that fails to run first leaves none, and one after a plan passed ends the run with that plan.
- An API error or an unmet precondition ends the run at once; a part with setup 1 rotated by 30° is refused before any request.
- Each run's stage sequence is pinned (Analyzing, Asking, Checking, Repairing after a failed check or an unreadable reply, Extending for the coverage round); every stage has its own page text, and the running text names the model the run was started with, not one picked later.

## Continuous stock and adaptive meshing

- Flat and ball cutter implicit fields are compared against an independent swept-solid membership calculation for horizontal strokes, ascending/descending ramps and vertical entries. Tests include finite flute extent and rotated/translated setup frames.
- Adaptive octree / manifold dual contouring produces triangle surfaces directly from continuous cutter history; the old occupancy grid no longer supplies rendered voxel faces. Tests verify finite vertices and two incident triangles per undirected mesh edge for the cylindrical cavity, ball-bottom cavity and sloped-channel fixtures.
- A 3 mm cylindrical wall fixture verifies radius error below 0.01 mm at Standard detail, improved accuracy over Draft, and flat floor positions. Its surface vertex count remains below 1% of the corresponding 256³ virtual domain. This is fixture evidence, not a general machining tolerance guarantee.
- A ball-bottom fixture checks spherical radius within 0.03 mm at Draft detail. A ramp fixture checks the analytic inclined cut surface within 0.02 mm and verifies a closed mesh.
- Cutter history is shared between snapshots. Consecutive collinear playback fragments merge into one continuous sweep; adding a new cut does not mutate an inherited snapshot.
- Background result tests reject surfaces from before a rewind, operation edit or detail change. Orbit/pan/zoom reuse the current mesh. While a newer snapshot is being meshed, the UI labels the retained surface Updating.
- The completed Fine pocket smoke used about 24,000 stored sweeps and 148,672 triangles at a 0.248 mm finest cell, taking about 2 seconds to mesh. The larger cumulative job reached about 48,000 sweeps; Standard updates took about 1.7–1.9 seconds. These are local measurements, not latency guarantees.
- Pocket completion, close-up Fine and Draft, rotated camera, Facing, Parallel, Waterline, inside/outside Contour, Drilling, flipped setup and restart screens were visually inspected. Flat faces, smooth pocket walls and tool-radius corners are visible. Fine sampling can still miss thinner features, and meshes are not certified collision/gouge results.
- Removed-volume readouts intentionally remain approximate: a separate bounded coarse occupancy grid supplies them. No dense fine-resolution volume is allocated for rendering.
